# Quark Drive

[Quark Drive](https://pan.quark.cn/) is a cloud storage service. This backend
uses the Quark Drive open platform and is deliberately limited to creating
directories, uploading files, and moving known file IDs.

## Important limitations

The open platform used by this backend does not provide directory enumeration
or file deletion. Consequently this backend cannot list, download, or remove
existing objects. It implements updates only for paths recorded in its local
state file.

Use it only for backups with all of the following safeguards:

- run `rclone copy` with `--no-traverse`;
- keep the configured `state_file` on persistent storage;
- do not run overlapping jobs that use the same state file;
- do not manually move or remove files in the active backup directory;
- do not use `sync`, `move`, `delete`, `purge`, `check`, `ls`, `mount`, or
  restore commands with this backend.

For example:

```console
rclone copy /srv/data quark:backups/current --no-traverse
```

The same destination can be reused by later runs. Files removed or renamed at
the source are not removed at the destination. Retention and restore must be
managed outside this backend, such as through the Quark Drive application.

## Configuration

Obtain the `access_token`, `refresh_token`, `user_id`, and `device_id` from an
authorized Quark Drive open-platform application, then run:

```console
rclone config
```

Choose `quark` and enter those values. Configure `refresh_token` for unattended
scheduled backups; when the access token expires, rclone rotates the tokens and
persists the replacements in its configuration.

For a scheduled job, set an explicit state path in the remote configuration,
for example:

```ini
state_file = /var/lib/rclone/quark-backup-state.json
```

The `root_folder_id` is normally left blank. Set it to a known directory FID to
place every backup below that directory, or explicitly set it to `0` for the
drive root. Replacing files directly in the platform default directory requires
`root_folder_id`; placing the backup in a named destination directory also
avoids this restriction.

## Upload behavior

Each source is spooled to a temporary file so rclone can calculate the MD5,
SHA-1, proof codes, and multipart SHA-1 state required by the open platform.
The host therefore needs enough temporary disk space for each concurrently
uploaded source file.

Uploaded files retain their source modification time with millisecond
precision. The backend does not expose hashes after upload because it cannot
look objects up again.

For a changed path, the backend uploads the new file into `.rclone-staging`,
moves the previous FID into `.rclone-versions`, and then moves the new FID into
the original directory. This provides repeatable backup updates without a
delete API; it is not a server-side atomic overwrite. Interrupted moves are
recorded and retried before that path is processed by the next run. Old
versions and empty staging directories are never deleted automatically.

The state file is the only path-to-FID index available to the backend. Losing
it, clearing the default rclone cache, changing the remote name, or reusing an
unrelated state file can create duplicate files. Set `state_file` explicitly
for scheduled jobs and include it in the host's own configuration backup.

### Standard options

Here are the Standard options specific to quark (Quark Drive open platform (upload-only)).

#### --quark-access-token

Long-lived access token issued by the Quark Drive open platform.

**NB** Input to this must be obscured - see [rclone obscure](/commands/rclone_obscure/).

Properties:

- Config:      access_token
- Env Var:     RCLONE_QUARK_ACCESS_TOKEN
- Type:        string
- Required:    true

#### --quark-refresh-token

Refresh token used to renew an expired access token.

**NB** Input to this must be obscured - see [rclone obscure](/commands/rclone_obscure/).

Properties:

- Config:      refresh_token
- Env Var:     RCLONE_QUARK_REFRESH_TOKEN
- Type:        string
- Required:    false

#### --quark-user-id

Quark Drive user ID used to generate upload proof codes.

Properties:

- Config:      user_id
- Env Var:     RCLONE_QUARK_USER_ID
- Type:        string
- Required:    true
